🔌 Ativando: app, Codex e CLI

Ativar o Astra é trivial quando você sabe onde olhar e frustrante quando não sabe: o seletor do chat pode não mostrar o modelo, o app precisa de atualização, o CLI lê um arquivo de configuração. Este módulo cobre as três superfícies com um comando de verificação em cada uma.

1

🖥️ ChatGPT: atualizar e achar o seletor

Sequência que resolve a maioria dos casos: confirme o plano (Pro; Plus também recebe, conforme o lançamento), abra o app de computador do ChatGPT, procure "verificar atualizações" no menu do app, atualize e relance. Depois, troque para a área de trabalho (o modo voltado a tarefas) e abra o seletor de modelo ali. No chat comum o seletor pode continuar mostrando só o modelo anterior.

Checklist de ativação no ChatGPT

1

Plano

Configurações → plano. Se for gratuito, o Astra não aparece.

2

Atualizar o app

Menu do app → verificar atualizações → instalar e relançar. Sem relançar, o seletor não muda.

3

Modo certo

Alterne do chat para a área de trabalho. Abra o seletor de modelo e escolha GPT-6 Astra.

4

Prova

Pergunte "qual modelo você é?" e confira o nome na resposta e no seletor. Os dois têm que bater.

✓ Sinais de que está ativo

  • ✓Seletor mostra GPT-6 Astra na área de trabalho
  • ✓Resposta a "qual modelo você é?" bate com o seletor
  • ✓Tarefas com navegador aparecem como opção

✗ Sinais de que não está

  • ✗Seletor só mostra o modelo anterior no chat comum (normal; troque de modo)
  • ✗App sem opção de atualizar (baixe a versão nova do site)
  • ✗Plano gratuito

💡 Versão do app importa mais que a data

O lançamento chega por atualização do app, não por data. Se um colega tem e você não, a diferença é quase sempre a versão instalada.

2

🧰 App do Codex: atualizar e selecionar

Atualize o app do Codex (menu → atualizar, ou baixe a versão nova). Crie ou abra um projeto apontando para a pasta de código. No seletor de modelo da sessão, escolha GPT-6 Astra. Ao lado costuma existir o esforço de raciocínio: medium para tarefas de edição e UI, high para depuração e migração. O que é medium de sobra não precisa de high.

Copie e rode

Prova de ativação no app do Codex: uma tarefa mínima com verificação

Resultado: um arquivo HELLO.md na raiz com o nome do modelo que você é e a data de hoje.
Onde: pasta atual.
Prova: saída de `cat HELLO.md`.
Não faça: não toque em nenhum outro arquivo.
Como verificar: O cat mostra o nome do modelo igual ao seletor. Apague o arquivo depois (ou peça para apagar e mostrar `ls`).

⚠️ Sessão antiga, modelo antigo

Sessões criadas antes da atualização podem manter o modelo anterior. Confira o seletor da sessão, não o padrão do app.

3

⌨️ Codex CLI: config.toml e flags

O CLI lê ~/.codex/config.toml. As duas chaves que importam agora são model e model_reasoning_effort. Tudo pode ser sobrescrito por flag numa chamada (-m, -c chave=valor). A documentação do Codex lista as demais; confira na sua versão.

Copie e rode

Atualizar o CLI, definir o Astra como padrão e conferir

# atualiza (npm) e confere a versão
npm i -g @openai/codex && codex --version

# define o modelo padrão e o esforço
cat >> ~/.codex/config.toml <<'EOF'
model = "gpt-6-astra"
model_reasoning_effort = "medium"
EOF

# diagnóstico: instalação, config, auth, runtime
codex doctor
Como verificar: `codex doctor` não acusa erro de config e `codex --version` mostra 0.153 ou mais novo. Se já existia uma linha `model =`, remova a duplicada: a última vence, mas fica ambíguo.

Copie e rode

Sobrescrever o modelo e o esforço só nesta chamada, sem editar o arquivo

codex -m gpt-6-astra -c model_reasoning_effort="high" "Qual modelo você é? Responda só o nome."
Como verificar: A resposta contém gpt-6-astra. Rode sem `-m` e confira que o padrão do config também responde certo.

4

📌 A conversa de trabalho fixada

O Codex lê um arquivo de instruções na raiz do projeto (AGENTS.md) e o aplica a toda sessão daquela pasta. Coloque ali o que você não quer repetir: como rodar, como testar, o que não tocar, o formato de prova que você aceita. O primeiro prompt da sessão principal pede um reconhecimento do projeto, e a partir dele você delega.

Copie e rode

AGENTS.md mínimo para um projeto web local

# Instruções para agentes

## Rodar e testar
- Subir: `npm run dev` (porta <PORTA>)
- Testar: `npm test`
- Nunca rode `npm run deploy` sem eu pedir explicitamente.

## Regras
- Não altere dependências (package.json) sem avisar antes.
- Não faça commit. Eu commito depois de verificar.
- Não mude comportamento em tarefas de "visual/CSS".

## Prova de conclusão
- Toda tarefa termina com: comando rodado + saída, ou screenshot, ou caminho do arquivo.
- Mostre a prova antes do resumo.
Como verificar: Abra uma sessão nova na pasta e peça "quais regras você deve seguir aqui?". A resposta cita o arquivo. Se não citar, o arquivo não está na raiz ou tem outro nome.

Copie e rode

Primeiro prompt da sessão principal: reconhecimento sem mudanças

Leia o projeto nesta pasta. Não altere nada.
Me devolva, em até 15 linhas:
1. O que o projeto faz e como sobe.
2. Onde ficam configurações de modelo/provedor de IA (arquivo e linha).
3. Os três arquivos que você tocaria para mudar o visual da tela principal.
4. Riscos que você vê (segredos em texto, ausência de testes, etc.).
Como verificar: Os caminhos citados existem (`ls` neles). Fixe a sessão com pin logo depois desta resposta.

💡 Um AGENTS.md por repo, não por sessão

Regra que vale para todo prompt vai no arquivo. Regra de uma tarefa vai no prompt. Misturar os dois faz o arquivo crescer até ninguém ler.

5

🛡️ Sandbox, aprovações e o que ele pode tocar

Dois controles independentes. O sandbox limita o que o processo consegue tocar (só leitura, escrita na pasta, acesso total). A política de aprovação decide quando ele pergunta antes de rodar algo (a pedido do modelo, nunca). O padrão sensato para uma máquina de trabalho: escrita na pasta do projeto, aprovação a pedido. Acesso total só quando o sandbox do sistema falha e a máquina é sua.

Copie e rode

Rodar uma tarefa com sandbox restrito à pasta e aprovação a pedido

codex -s workspace-write -a on-request "Liste os arquivos que você mudaria para trocar o modelo de IA deste projeto. Não mude nada ainda."
Como verificar: O agente responde com a lista e não pede aprovação (não executou nada de escrita). Se pedir, leia o comando antes de aprovar.

✓ Aprove sem ler de novo

  • ✓Leitura de arquivos e `grep`
  • ✓Rodar testes e build do projeto
  • ✓Editar arquivos dentro da pasta
  • ✓Subir o servidor de desenvolvimento

✗ Leia o comando inteiro

  • ✗Qualquer `rm`, `git reset`, `git push`
  • ✗Instalação global (`npm i -g`, `pip install`)
  • ✗Comandos fora da pasta do projeto
  • ✗Qualquer coisa com token, chave ou senha

⚠️ Acesso total é um modo, não um padrão

Se o sandbox do seu sistema falhar (acontece em alguns kernels Linux), o CLI oferece desligar o sandbox. Faça isso por projeto que você controla, nunca no config global de uma máquina compartilhada. E nunca junto com aprovação "never".
